# 设计-WebDAV同步

> 状态：定稿 ｜ 版本：v15 ｜ 关联：D5

## 定位

1 台设备 + WebDAV 仅作**换机备份/防丢安全网**。备份式：数据库文件即真相，无行级同步、无冲突处理。

## 备份内容

```
backup_YYYYMMDD_HHMMSS.zip
├─ account.db          # drift SQLite（先 checkpoint 再拷贝）
└─ images/             # 记账图片目录（私有目录整体打包）
```

- **db 一致性**：备份前执行 `PRAGMA wal_checkpoint(FULL)`，确保 WAL 合并，拷贝出的库是完整快照
- 图片与 db 一起打包：换机恢复后流水、图片完整对应
- 暂不加密（自用 + 凭据已安全存储）；如需第三方云明文顾虑，后续可加 AES 可选开关——接口在 Repository 层预留

## 保留策略

- 服务器上**保留最近 5 份**：上传新备份成功后，列出同目录 `backup_*.zip`，删除最早的超出份数
- 防占满 WebDAV 空间（坚果云等有上传流量限制）

## 完整性校验

- 上传前：本地计算 db+图片目录的 SHA-256 摘要，写入 zip 内 `manifest.json`
- 恢复时：下载 → 校验 zip CRC → 校验 manifest 摘要一致 → 才允许解包；任一不符提示"备份文件损坏"，不触碰本地数据

## 恢复流程（有保护）

```
确认 → 自动备份当前库到服务器（保险）→ 下载目标备份 → 校验 → 解包到临时目录
    → 关闭 drift 连接 → 原子替换 db 与 images → 重开连接 → 全局刷新（走 Repository 单例）
```

- 恢复前自动备份当前库，双保险，防止"恢复后想回退"
- **连接生命周期**：drift 连接运行中不能直接替换 db 文件——必须先关闭连接，替换完成后再重开，最后通知 UI 全局刷新
- 替换用"临时目录 + 原子改名"，避免写一半崩了库损坏

## 凭据与配置

- 存储：`flutter_secure_storage`（Android Keystore 加密），**不用** SharedPreferences
- 配置项（设置页）：服务器地址 / 用户名 / 密码（应用密码）/ 备份目录路径（如 `/记账备份/`）
- 配置保存时立即 `PROPFIND` 测通，失败提示不改配置

## 触发时机

- 手动：设置页"立即备份" / "立即恢复"
- 自动：App 启动时检查 `距上次备份 > 24h` 且网络可用 → 静默备份；失败跳过，下次启动再试（不做 WorkManager 常驻任务，自用够用）
