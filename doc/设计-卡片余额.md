# 设计-卡片余额

> **v16 重构提示**：卡片余额将被账户余额（`account` + 收支/转账流水）取代；本文双流水方案仅作历史参考，见 `设计-账户资产模型.md` §4.1/§5。

> 状态：定稿 ｜ 版本：v15 ｜ 关联：ADR-002 / ADR-013（充值）

## 决策

**余额不存快照，纯聚合计算（单一数据源）。**

```
余额 = card.initial_amount + Σ(recharge.credit_amount, 挂本卡)
                            − Σ(消费流水 type='card' 挂本卡)
```

- 充值 = **双流水职责分离**（ADR-013/014）：
  - `expense`：金额=实付，挂卡片自动类别，**永久独立**（计支出，删卡不动）
  - `recharge`：credit_amount=到账，**虚空**（随卡片删除，仅驱动余额）
- **充值 200 送 200**：expense 200（支出）+ recharge credit 400（余额+400）
- **口径**：储值卡充值支出走 expense（计支出）、储值卡消费不计支出（余额消耗）；非储值卡消费计支出——详见 `设计-数据模型.md` §2.1
- **删储值卡**：recharge + 消费流水随删；expense 询问是否删除（默认保留，类别归【卡片】(2)）——支出与卡生命周期解耦，无需类型转换，详见 `设计-删除联动.md`
- **不提供直接编辑余额**：余额修正 = 充值/消费动作（保持聚合一致性）

## 方案对比

| 方案 | 机制 | 问题 |
|---|---|---|
| A 快照存储 | 余额字段 + 流水明细双写 | 删/改流水需同步回滚余额，漏一处永久不一致 |
| **B 聚合计算** | 初始金额 + 充值/消费流水实时聚合 | 一致性与生俱来；代价是每次展示一次本地聚合查询 |
| C 充值改初始金额 | 充值直接改 initial_amount | 无充值历史可查；余额与流水脱节 |

## 权衡

- 放弃：O(1) 直接读余额、直接编辑余额
- 获得：一致性由数据结构保证，不依赖代码纪律；删流水/改金额自动正确；充值历史完整可查
- SQLite 本地聚合毫秒级，单卡流水千级以内，自用无性能风险
- 若未来增长到万级，再引入物化视图/缓存，接口不变（Repository 内聚）

## 实现约定

- `card.isStoredValue=false`（非储值卡：bank 或 custom 非储值）：消费=真实支出，计入统计；无充值概念
- `card.isStoredValue=true`（储值卡：stored 或 custom 储值）：充值(实付)计支出、消费不计支出（仅余额扣减与明细展示）
- Repository 提供 `getCardBalance(cardId)`：事务内聚合，避免与写入并发读到中间态
- 展示：余额为负说明数据异常（消费超扣），UI 标红提示而非静默
