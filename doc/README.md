## 核心设计决策（索引）

| # | 决策 | 要点 | 详见 |
|---|---|---|---|
| D1 | 金额存储 | 一律整数分 `int`；Excel导入 `round(元×100)` | 数据模型 |
| D2 | 账户中心 | 现金/银行/电子钱包/储值卡/信用卡/存单/贷款统一为 `account` | 账户资产模型 |
| D3 | 收支流水 | 用户只记收入/支出；内部 transfer 仅资产动作使用 | 数据模型 |
| D4 | 余额派生 | 余额=期初+收入−支出+转入−转出；不存快照；不做净资产 | 数据模型 |
| D5 | 资产详情 | card/deposit/loan 与 account 1:1；存单/贷款/信用卡独立详情 | 数据模型 |
| D6 | 关联交易组 | 充值/还款/存单动作成组，`group_id + group_kind`；资产交易 locked | 数据模型 |
| D7 | 删除/归档 | 有流水账户只归档；类别删除归【其他】/删流水；存单可删记录 | 交互规格 |
| D8 | 备份 | zip(db+图片)、保留最近5份、CRC校验；密码入 Keystore | WebDAV同步 |
| D9 | 报表口径 | 支出=实际付出；储值卡充值/信用卡消费/贷款月供计支出，消费/还款不重复 | 报表 |
| D10 | 账户表单 | 银行卡/储值卡/贷款可新增/编辑；储值卡默认类别联动；贷款余额为负 | 实现规格/交互规格 |

> v15 的卡片/周期/充值模型与 D2/D4/D6 等旧编号仅作历史参考；v16 以本表、《设计-账户资产模型》和四份 v16 文档为准。

## 架构分层

```
UI 层（页面/组件，消费仓库）
   ↓
仓库层 Repository（唯一数据出入口：增删改查、聚合、导入）
   ↓
数据层 drift（账户/交易/类别/详情/计划表 + 约束）  ←→  同步层（WebDAV 备份/恢复）
```

- 页面不直接碰数据库，一律走 Repository —— 为 WebDAV 恢复（整库替换后刷新）留单一入口。
- 备份式同步无行级同步状态，数据库文件即真相。
