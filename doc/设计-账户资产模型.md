# 设计-账户资产模型（v16 重构主文档）

> 状态：**已确认（方案 A）** ｜ 版本：v16 ｜ 取代 v15 的 `card / period / recharge` 特例模型
> 目标：用「账户 + 交易」统一管理收支、资产、负债、存单、贷款、信用卡；**UI 保持简单，模型保持正确**。
> 关联：`DESIGN.md`（视觉不变）、`ANDROID_PLAN.md`（批次）、`设计-数据模型.md`（v15 旧模型，待本文替代）

---

## 1. 结论

- **账户中心**：一切余额都落在 `account` 上，资产为正、负债为负。
- **内部三类交易**：`income / expense / transfer`；**用户记账只看到收入/支出**，转账仅由资产动作内部生成。
- **扩展详情**：存单、贷款、卡片、周期规则各自一张 detail/plan 表，不污染交易表。
- **余额派生**：`余额 = 期初 + 收入 − 支出 + 转入 − 转出`，不存快照。
- **账户余额**：所有余额由流水派生；报表只做收入/支出/结余，不做净资产等第二口径。
- **不做复式记账**：复杂动作（贷款还款、充值赠送、存单支取）用 `group_id` 生成一组关联交易即可。
- **UI 四 Tab**：首页 / 报表 / **资产** / 我的（“卡片”升级为“资产”）。

## 2. 旧模型的问题

| 问题 | 旧模型表现 | 新模型解决 |
|---|---|---|
| 没有账户层 | 银行卡余额不随消费变化；储值卡靠特殊聚合 | 所有余额统一由账户流水派生 |
| 交易类型特例化 | `card / period / recharge` + `channel / credit_amount` | 只保留收入/支出/转账 |
| 周期支出混概念 | 房贷（负债）和电话费（周期账单）同表 | `loan_detail` 与 `recurring_rule` 分离 |
| 房贷本金算支出 | 月供全额计支出，报表虚高 | 本金=转账，利息=支出 |
| 储值卡充值算支出 | 充值即支出，消费不再计 | 充值=转账，消费=支出 |
| 资产/负债分散 | 卡片、存单、贷款各自为政 | 统一账户列表（只展示余额，不做净资产报表） |
| 存单无处安放 | 只能新增孤立表 | 存单=账户类型 + deposit_detail |

> 核心判断：**电子存单不是“再加一个页面”，而是暴露了资产/负债层的缺失。**

## 3. 模型总览

```
account（现金/银行卡/电子钱包/储值卡/信用卡/存单/贷款）
   ↑ 1:1 扩展
   ├─ card_detail     卡片：默认消费类别、有效期、信用额度、账单日
   ├─ deposit_detail  存单：利率、存期、起存/到期、实际利息
   └─ loan_detail     贷款：原始本金、利率、期限、下次还款

transaction（income / expense / transfer）
   ├─ account_id       支出=付款账户；收入=收款账户；转账=转出账户
   ├─ to_account_id    仅转账：转入账户
   ├─ category_id      收入/支出必填；转账为空
   └─ group_id         关联交易组（贷款还款、充值赠送、存单支取）

category           收入/支出类别（两级，保留【其他】）
recurring_rule     周期账单计划（不是账户，不是流水）
settings           默认账户 / WebDAV / 删除默认行为
```

**账户类型**

| type | 含义 | 余额符号 | 可作为支出账户 | 说明 |
|---|---|---|---|---|
| cash | 现金 | 正 | 是 | 可选，不再强制“默认账户虚拟卡” |
| bank | 银行卡/借记卡 | 正 | 是 | 余额随收支/转账变化 |
| ewallet | 支付宝/微信等 | 正 | 是 | 与 bank 同构 |
| stored | 储值卡/购物卡/理发卡 | 正 | 是 | 消费=支出；充值=转账 |
| credit | 信用卡 | 负 | 是 | 消费为负；还款=转账 |
| deposit | 电子存单/定期 | 正 | 否 | 只能转账进出；利息=收入 |
| loan | 房贷/车贷/消费贷 | 负 | 否 | 还款=本金转账+利息支出 |

> 投资账户（基金/股票）暂不做；未来可加 `investment`，用市值快照 + 收益调整，不纳入本期。

## 4. 表结构

### 4.1 account 账户表

| # | 字段 | 类型 | 可空 | 默认 | 说明 |
|---|---|---|---|---|---|
| 1 | id | INTEGER | 否 | 自增 | PK |
| 2 | type | TEXT | 否 | — | cash/bank/ewallet/stored/credit/deposit/loan |
| 3 | name | TEXT | 否 | — | 账户名（如“招行储蓄卡”“银座购物卡”） |
| 4 | institution | TEXT | 是 | NULL | 银行/平台名（如“招商银行”“支付宝”） |
| 5 | icon | TEXT | 否 | — | 内置图标名 |
| 6 | opening_balance | INTEGER | 否 | 0 | 期初余额，分；资产正、负债负 |
| 7 | sort_order | INTEGER | 否 | 0 | 列表排序 |
| 8 | archived | INTEGER | 否 | 0 | 归档；0/1 |
| 9 | note | TEXT | 是 | NULL | 备注 |
| 10 | created_at | INTEGER | 否 | — | Unix 毫秒 |
| 11 | updated_at | INTEGER | 是 | NULL | 更新时间 |

```sql
CREATE TABLE account (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  type TEXT NOT NULL CHECK (type IN ('cash','bank','ewallet','stored','credit','deposit','loan')),
  name TEXT NOT NULL,
  institution TEXT,
  icon TEXT NOT NULL,
  opening_balance INTEGER NOT NULL DEFAULT 0,
  sort_order INTEGER NOT NULL DEFAULT 0,
  archived INTEGER NOT NULL DEFAULT 0 CHECK (archived IN (0,1)),
  note TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER,
  CHECK (type NOT IN ('credit','loan') OR opening_balance <= 0)
);
```

- **不存 balance**；余额由 `account_balance` 查询派生。
- 负债账户期初为负（房贷剩余本金、信用卡欠款）。
- 归档只影响列表/选择器，不删除历史；归档前建议余额为 0（非 0 给出提示）。

### 4.2 transaction 交易表

| # | 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|---|
| 1 | id | INTEGER | 否 | PK |
| 2 | type | TEXT | 否 | income/expense/transfer |
| 3 | amount | INTEGER | 否 | 分，恒正，CHECK>0 |
| 4 | occurred_at | INTEGER | 否 | 交易时间，Unix 毫秒 |
| 5 | category_id | INTEGER | 是 | 收入/支出必填；转账为空 |
| 6 | account_id | INTEGER | 否 | 支出=付款账户；收入=收款账户；转账=转出 |
| 7 | to_account_id | INTEGER | 是 | 仅转账：转入账户 |
| 8 | group_id | TEXT | 是 | 关联交易组 |
| 9 | group_kind | TEXT | 是 | 组类型：loan_payment/recharge/credit_repay/deposit_transfer/deposit_settle/deposit_renew |
| 10 | locked | INTEGER | 否 | 1=由资产动作生成，禁止在流水列表改删 |
| 11 | note | TEXT | 是 | 备注 |
| 12 | image_path | TEXT | 是 | 凭证图片 |
| 13 | created_at | INTEGER | 否 | 创建时间 |
| 14 | updated_at | INTEGER | 是 | 更新时间 |

```sql
CREATE TABLE transaction (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  type TEXT NOT NULL CHECK (type IN ('income','expense','transfer')),
  amount INTEGER NOT NULL CHECK (amount > 0),
  occurred_at INTEGER NOT NULL,
  category_id INTEGER,
  account_id INTEGER NOT NULL,
  to_account_id INTEGER,
  group_id TEXT,
  group_kind TEXT CHECK (group_kind IS NULL OR group_kind IN
    ('loan_payment','recharge','credit_repay','deposit_transfer','deposit_settle','deposit_renew')),
  locked INTEGER NOT NULL DEFAULT 0 CHECK (locked IN (0,1)),
  note TEXT,
  image_path TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER,
  FOREIGN KEY (category_id) REFERENCES category(id),
  FOREIGN KEY (account_id) REFERENCES account(id),
  FOREIGN KEY (to_account_id) REFERENCES account(id),
  CHECK ((type='transfer') = (to_account_id IS NOT NULL)),
  CHECK ((type='transfer') = (category_id IS NULL)),
  CHECK (to_account_id IS NULL OR to_account_id != account_id)
);
CREATE INDEX idx_trans_occurred ON transaction(occurred_at);
CREATE INDEX idx_trans_account ON transaction(account_id);
CREATE INDEX idx_trans_to_account ON transaction(to_account_id);
CREATE INDEX idx_trans_category ON transaction(category_id);
CREATE INDEX idx_trans_group ON transaction(group_id);
```

**余额口径**

```
balance(account) =
  opening_balance
  + Σ income.account_id = id
  + Σ transfer.to_account_id = id
  − Σ expense.account_id = id
  − Σ transfer.account_id = id
```

### 4.3 category 类别表（简化）

| 字段 | 说明 |
|---|---|
| id / name / icon / type / parent_id | 同旧模型，保留两级 |
| is_preset | 系统预设 |
| is_fixed | 仅【其他】=1，禁删改 |

- **删除 `is_auto` 与【卡片】总分类**：账户模型下，交易直接挂账户，不再需要“卡片兜底类别”。
- 预设新增：收入「利息」「赠送」；支出「利息支出」「手续费」。
- 删除类别：未使用直接删；已使用则询问“流水归【其他】/删除流水”。

### 4.4 card_detail 卡片详情表

| 字段 | 说明 |
|---|---|
| account_id | PK/FK → account，1:1 |
| default_category_id | 储值卡消费默认类别；可空 |
| expire_at | 有效期；可空 |
| card_tail | 卡号后四位；可空 |
| credit_limit | 信用额度（credit）；可空 |
| billing_day | 账单日（credit，1–28）；可空 |
| repayment_day | 还款日（credit，1–28）；可空 |

> 银行卡/储值卡/信用卡共用 account.type；card_detail 只放“卡”属性。
> 银行卡不强制建 card_detail；信用卡建议必填额度/账单日。

### 4.5 deposit_detail 存单详情表

| 字段 | 说明 |
|---|---|
| account_id | PK/FK → account，1:1 |
| certificate_no | 存单号；可空 |
| principal | 初始本金，分；账户期初=本金 |
| rate_bp | 年利率基点（325=3.25%） |
| term_months | 存期 1/3/6/12/24/36/60 |
| start_at | 起存日 |
| maturity_at | 到期日（创建/编辑时计算） |
| closed_at | 支取/转存日；非空=关闭 |
| close_type | maturity/early/renew |
| actual_interest | 实际利息，分；关闭时写 |

- 状态派生：未关闭 + 未到期=进行中；未关闭 + 已到期=待处理；已关闭=已支取/已转存。
- 预计利息派生：`round(principal × rate_bp / 10000 × term_months / 12)`。
- 存单本金/利息的账户流水见 §6.6；**不把本金记成支出/收入**。
- v1 只支持到期一次性还本付息；按月/季付息放 v2（届时增加收息记录或 `interest_payment` 表）。

### 4.6 loan_detail 贷款详情表

| 字段 | 说明 |
|---|---|
| account_id | PK/FK → account，1:1 |
| kind | mortgage/car/consumer/other |
| original_principal | 原始本金，分 |
| rate_bp | 年利率基点 |
| term_months | 总期数/期限（月） |
| start_at | 放款/起始日 |
| next_due_at | 下次还款日；用户维护 |
| per_amount | 每期还款额，分；可空 |
| repayment_method | equal_principal_interest / equal_principal / interest_only / other |

- 剩余本金 = `-account.balance`（负债余额绝对值）。
- 已还本金 = `original_principal - 剩余本金`。
- 还款：本金=转账（银行→贷款），利息=支出；两条交易同 `group_id`。
- 不自动生成还款计划；v1 由用户录“还款金额 + 利息”，本金自动=金额−利息。

### 4.7 recurring_rule 周期规则表

| 字段 | 说明 |
|---|---|
| id | PK |
| name | 如“电话费” |
| type | income/expense |
| amount | 每期金额，分 |
| category_id | 类别 |
| account_id | 付款/收款账户 |
| frequency | weekly/monthly/quarterly/yearly |
| next_due_at | 下次到期日 |
| enabled | 0/1 |
| note | 备注 |

- 规则是“计划”，不是账户/流水。
- 到期后在首页「待办」显示；点击打开预填记账 Sheet，保存后生成普通交易并推进 `next_due_at`。
- **不后台自动记账**，避免用户不知情生成流水。

### 4.8 settings 设置表

保留 KV 结构：

| 键 | 说明 |
|---|---|
| webdav_url / webdav_username / webdav_dir | WebDAV 配置 |
| default_account_id | 默认记账账户（支出默认选中） |
| del_category | keep/delete（删除类别默认行为） |

- 删除 `del_card` / `del_period`：账户改为归档，周期计划直接删除（不影响历史流水）。
- 密码仍入 Keystore；备份时间戳仍入 shared_preferences。

## 5. 统计口径

### 5.1 交易类型（内部）

> 数据模型保留 `transfer` 只用于充值/存单/贷款/信用卡还款等资产动作；记账 Sheet 不暴露“转账”。

| 类型 | 影响 |
|---|---|
| income | 收入；账户余额增加；进入收入报表 |
| expense | 支出；账户余额减少；进入支出报表 |
| transfer | 账户间转移；**不计收入/支出**；仅用于余额调整/资产动作 |

### 5.2 支出口径（固定规则，无开关）

**支出 = 实际付出的钱。收入 = 实际收到的钱。** 不做“真实成本/消费发生制/现金流”等用户选项，避免同一笔钱重复计算。

| 场景 | 计入「支出」 | 规则 |
|---|---|---|
| 餐饮/购物/交通等消费 | ✅ | 正常支出 |
| 储值卡充值 | ✅ | 充值时计支出；卡内消费只扣余额，不再计支出 |
| 储值卡消费 | ❌ | 充值已计，消费只更新卡余额/明细 |
| 信用卡消费 | ✅ | 刷卡时计支出 |
| 信用卡还款 | ❌ | 消费已计，还款不再计 |
| 房贷/车贷月供 | ✅ **整笔** | 月供 6,800 全部计支出，不拆本金/利息 |
| 存单购买/到期本金 | ❌ | 存单是储蓄记录，本金不算花掉/收入 |
| 存单利息 | 收入 | 实际利息计入收入 |
| 手续费/其他利息 | ✅ | 实际付出计支出 |
| 账户间转账（内部） | ❌ | 仅用于余额调整，不进入收支 |

**核心原则：一笔钱只计一次。**

- 储值卡：充值时计支出 → 消费不再计。
- 信用卡：刷卡时计支出 → 还款不再计。
- 房贷：还款时计支出 → 放款不计收入。
- 存单：购买不计支出 → 到期本金不计收入 → 只有利息计收入。

> 用户界面只展示「收入 / 支出 / 结余」；不出现“真实成本、净资产、消费口径”等概念。
> 账户余额/卡片余额/存单余额只做辅助展示，不参与支出口径。

### 5.3 账户余额（内部辅助）

```
余额 = opening_balance
     + Σ income
     + Σ transfer 转入
     − Σ expense
     − Σ transfer 转出
```

- 余额用于卡片/存单/贷款详情展示，不作为报表指标。
- 不做净资产、总资产、资产负债率等页面。
- 余额不一致时以流水为准，账户期初仅作起点。

### 5.4 报表

> 报表页交互/布局/指标详见 `设计-报表.md`（周/月/季/年 + 支出/收入切换 + 趋势/对比 + 分类/单笔排行）。

- **收支**：收入 / 支出 / 结余（收入−支出）。
- **支出构成**：按支出类别聚合。
- **收入构成**：按收入类别聚合（含利息/赠送）。
- **趋势**：周/月/季/年的收入、支出折线。
- 不做“真实成本”“净资产趋势”“资产构成”等第二口径；需要时后续再加。

**报表查询规则（实现口径）**

```
支出 = Σ expense
     + Σ transfer WHERE group_kind = 'loan_payment'   -- 月供整笔
     + Σ transfer WHERE group_kind = 'recharge'        -- 储值卡充值实付
     − Σ expense WHERE account.type = 'stored'         -- 储值卡消费不重复计

收入 = Σ income
```

- 贷款还款组：transfer 本金 + expense 利息 → 支出取整组。
- 储值充值组：transfer 实付 + income 赠送 → 支出取 transfer 实付；赠送计收入。
- 信用卡还款组/存单组：transfer 不计支出；存单利息计收入。
- 普通账户间转账：不计支出。

## 6. 关键流程

### 6.1 普通支出

```
记账 Sheet：支出 ¥38，餐饮，账户=支付宝
→ transaction(type=expense, amount=3800, account=支付宝, category=餐饮)
→ 支付宝余额 −38
```

### 6.2 普通收入

```
收入 ¥23,500，工资，账户=招行卡
→ transaction(type=income, amount=2350000, account=招行卡, category=工资)
```

### 6.3 转账

```
招行卡 → 支付宝 ¥1,000
→ transaction(type=transfer, amount=100000, account=招行卡, to=支付宝)
→ 两边余额一增一减，收支报表不变
```

### 6.4 储值卡

**充值 200 送 200**

```
group_id=g1, group_kind=recharge
1) transfer  bank → stored   amount=20000
2) income    stored           amount=20000  category=赠送
→ 储值卡 +400，银行卡 −200，收入 +200
→ 报表支出 +200（充值，计入支出）
```

**消费 50**

```
expense  amount=5000  account=stored  category=购物
→ 储值卡 −50；不再计支出（充值已计）；卡内消费明细可见
```

**归档时余额 30 未用**

```
expense  amount=3000  account=stored  category=其他（余额核销）
→ 支出 +30，余额归零
```

### 6.5 信用卡

```
消费 300：expense  account=信用卡  category=餐饮
还款 300：transfer  bank → 信用卡  group_kind=credit_repay
→ 消费计支出；还款不计支出（避免重复）；报表单列“本月还款”
→ 信用卡余额回到 0
```

### 6.6 贷款

**放款 100 万到银行卡**

```
transfer  loan → bank  amount=100000000
→ 贷款 −100 万，银行卡 +100 万，不计收支
```

**月供 6,800，其中利息 1,800**

```
group_id=g2, group_kind=loan_payment
1) transfer  bank → loan   amount=500000   （本金）
2) expense   bank          amount=180000   （利息，category=利息支出）
→ 贷款余额减少 5,000；银行卡减少 6,800
→ 流水展示一条「房贷还款 ¥6,800」
→ 支出 +6,800（整笔）；不再拆真实成本/净资产
```

### 6.7 电子存单

**购买 10 万（从银行卡转入）**

```
transfer  bank → deposit  amount=10000000
→ 存单余额 +10 万；支出 0
```

**到期支取，利息 9,750**

```
group_id=g3, group_kind=deposit_settle, locked=1
1) transfer  deposit → bank  amount=10000000  （本金）
2) income    bank            amount=975000    （利息，category=利息）
→ 存单账户余额 0；收入 +9,750；本金不计收入；支出不变
```

**转存（本息转存）**

```
group_kind=deposit_renew, locked=1
1) income    new_deposit  amount=975000   （利息）
2) transfer  old_deposit → new_deposit  amount=10000000（本金）
→ 旧存单关闭；新存单余额 109,750；本金不计收支
```

**提前支取**

```
group_kind=deposit_settle, locked=1
1) transfer  deposit → bank  amount=principal
2) income    bank            amount=actual_interest  （可为 0）
→ close_type=early；本金不计收支
```

### 6.8 周期账单

```
规则：电话费 99/月，账户=支付宝
到期待办 → 点击“记一笔” → expense 99，category=通讯，account=支付宝
→ 生成流水；next_due_at +1 月
```

### 6.9 手续费

```
expense  amount=手续费  account=付款账户  category=手续费
```

## 7. 旧 → 新映射

| 旧 v15 | 新 v16 |
|---|---|
| `card.kind=bank` | `account.type=bank` |
| `card.kind=stored` | `account.type=stored` + `card_detail` |
| `card.kind=custom` | `account.type=stored`（或 bank）+ `card_detail`，用 `is_stored_value` 语义并入 type |
| `recharge` 双流水 | 转账（实付）+ 收入（赠送） |
| `type=card` 消费 | `expense`（account=储值卡） |
| `channel` | 删除；由 `account_id` 表达 |
| `credit_amount` | 删除；由转账+收入表达 |
| `period` term（房贷/车贷） | `account.type=loan` + `loan_detail` |
| `period` recurring（电话/停车） | `recurring_rule` |
| `type=period` 还款 | 转账（本金）+ 支出（利息）；报表「支出」按整笔月供计 |
| 默认账户虚拟卡 | `settings.default_account_id`（真实账户） |
| 【卡片】总分类 / 自动类别 | 删除；交易直接挂账户 |
| 存单独立表方案 | `account.type=deposit` + `deposit_detail` |

## 8. UI / 信息架构

### 8.1 四 Tab

```
首页 / 报表 / 资产 / 我的
```

- 首页：本月收入/支出/结余 + 最近流水 + 中央「记一笔」；待办用右上角入口。
- 报表：收支 + 支出/收入构成 + 趋势；不做净资产/真实成本。
- 资产：卡片/存单/贷款列表与余额（辅助），不展示净资产/总资产。
- 我的：默认账户、类别、Excel 导入、WebDAV 备份、删除默认行为、关于。

### 8.2 资产页（辅助列表）

```
卡片
  招行卡       余额 ¥32,000
  银座购物卡   余额 ¥850
存单
  招行3年存单  本金 ¥100,000 · 3.25% · 2027-06-01
贷款
  房贷         剩余 ¥1,024,300 · 下次还款 07-01
```

- 只展示余额/本金/下一节点，不做净资产、总资产、负债率。
- 资产/负债金额可按语义着色（资产中性、负债 liability）。
- 点击进入详情；右上 `+` 添加卡片/存单/贷款/信用卡/储值卡。

### 8.3 记一笔

```
[ 支出 ] [ 收入 ]
金额
类别（支出/收入）
账户/卡片（可选）
日期 / 备注 / 图片
```

- **记账 Sheet 只做收入/支出**，不出现“转账”类型。
- 转账只作为内部动作：储值卡充值、存单购买/支取、贷款还款、信用卡还款，从详情页发起，不在流水 Sheet 里选。
- 账户过滤：
  - 支出：cash / bank / ewallet / stored / credit
  - 收入：cash / bank / ewallet / stored / deposit
- 存单/贷款不能作为普通支出账户；只能在详情页做资产动作。
- 默认账户取 `settings.default_account_id`；未设置取第一个非归档资产账户。

### 8.4 账户详情 / 上下文动作

- 银行卡/电子钱包：编辑、转账、归档、最近流水。
- 储值卡：充值、消费记录、编辑默认类别、归档（余额需核销）。
- 信用卡：还款、账单日/额度、消费记录、编辑。
- 存单：编辑、提前支取、到期支取、转存、删除/归档、存单详情。
- 贷款：还款（本金+利息）、提前还款、编辑、剩余本金/进度。
- 周期规则：编辑、启用/停用、立即记一笔。

**复杂动作一律在详情页，不塞进通用记账 Sheet**。

### 8.5 首页待办

- 存单 30 天内到期 / 已到期。
- 信用卡还款日临近。
- 周期规则到期。
- 最多展示 3 条；点击直达对应详情或预填记账。

### 8.6 视觉

沿用 `DESIGN.md` 令牌，不新增色相：

- 资产/账户：primary 靛；负债：liability 橙；收入/利息：income 绿。
- 存单进度条用 primary；贷款进度用 liability。
- 储值卡渐变仅保留给储值卡实体，存单/账户用白底卡片。

Future<void> updateAccount(int id, AccountInput input);

Future<void> repayLoan(int loanId, LoanPaymentInput input);        // 本金转账 + 利息支出

## 10. 删除 / 归档 / 锁定

| 对象 | 规则 |
|---|---|
| 交易 | 普通交易可改删；`locked=1` 的资产交易只能在详情页撤销 |
| 交易组 | 删除时询问“删除整组？”；贷款还款/充值赠送整组删 |
| 账户 | 无流水可硬删；有流水只能归档；归档前余额应为 0，非 0 提示“先转账清零” |
| 类别 | 未使用直接删；已使用询问“归【其他】/删除流水” |
| 存单 | 删除=归档账户；已记利息收入保留；存单详情提供“撤销支取”（v1 可选） |
| 贷款 | 归档账户；历史还款流水保留 |
| 周期规则 | 直接删；已生成流水不受影响 |
| 信用卡 | 归档；欠款需先还清或保留负余额（提示） |

## 13. 验收与测试

- 余额：`期初 + 收入 − 支出 + 转入 − 转出` 与账户详情一致。
- 转账：两边余额变化、收支报表不变。
- 储值卡：充值计支出；消费只扣余额、不再计支出；赠送计收入；核销后余额 0。
- 信用卡：消费计支出；还款不计支出；欠款余额正确。
- 贷款：流水展示整笔月供；支出统计含整笔；剩余本金正确。
- 存单：购买/到期本金不计收支；利息收入正确；状态边界（到期日当天=待处理）。
- 删除/归档：有流水账户不能硬删；类别删除归【其他】；locked 交易不可改删。
- 备份恢复：所有新表 + 图片完整；恢复后余额刷新。
- 金额：整数分、tnum、千分位、fitAmount；禁止浮点落库。

## 14. 默认决策（可调整）

1. **支出口径**：固定“支出 = 实际付出（消费 + 储值卡充值 + 还贷整笔 + 其他利息/费用）”；消费/还款不重复计；不做真实成本/净资产/开关。储值卡默认充值计支出，消费只扣余额。
2. **信用卡/贷款**：纳入 v1（现有房贷/车贷必须保留），批次 3/5 实现。
3. **周期规则**：手动确认生成流水，不后台自动记账。
4. **期初余额**：已有资产用 opening_balance 录入；新购存单可选择“从账户转入”或直接期初。
5. **账户删除**：有流水一律归档，不硬删。
6. **存单付息**：v1 只做到期一次性；按月/季放 v2。
