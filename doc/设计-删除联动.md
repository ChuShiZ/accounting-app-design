# 设计-删除联动

> 状态：定稿 ｜ 关联：D3 / ADR-005（本决策）
> 字段引用一律 snake_case 对齐 DDL（见 `设计-数据模型.md`）

## 决策

删除操作一律**询问 + 可配置默认值**（设置项，避免每次点确认）。

## 规则

### 1. 删除类别

- **【其他】类别（id=1, is_fixed=1）常驻，禁止删除/改名/改类型**
- 删除其他类别时询问：*「删除关联的 N 条流水？」*
  - 选**删除** → 级联删该类别下全部流水
  - 选**保留** → 流水 `category_id` 改指【其他】(id=1)，数据不丢
- 设置项：`删除类别默认行为 = 删除 | 保留`（默认：**保留**，安全优先）

### 2. 删除周期支出

- 若该周期支出已生成还款流水，询问：*「删除关联的 N 条还款流水？」*
  - 选**删除** → 级联删还款流水（`type='period' AND period_id=id`）
  - 选**保留** → 流水保留，`period_id` 置空，**type `period`→`expense` + `category_id`→【其他】(1)**（语义转为普通支出，备注保留原周期名；否则撞 CHECK 约束与 FK）
- **自动类别**（创建时生成的 is_auto 同名类别）：无普通流水引用 → 一并删除；仍被普通流水引用 → 流水归【其他】后删类别
- 无还款流水时直接删除，不询问
- 设置项：`删除周期支出默认行为 = 删除 | 保留`（默认：**保留**）

### 3. 删除卡片（按卡型区分）

> **默认账户虚拟卡（is_system=1）系统内建：无删除入口、不可删除/编辑**（对齐原型，ADR-023）；仅真实卡片可删。

**储值卡（is_stored_value=1）——虚空流水随删、支出流水不动：**
- 询问：*「删除 N 条消费流水？M 笔充值支出是否保留（推荐保留）？」*
  - **消费流水**（type='card'）：随删——卡没了余额消耗记录失去语境（虚空流水）
  - **充值余额流水**（type='recharge'）：随删——虚空流水
  - **充值支出流水**（type='expense'）：**默认保留**——真实支出与卡生命周期解耦，无需类型转换；保留时 `category_id`→**【卡片】(2)**（自动子分类回收）；选择删除则连删
- 删除提示明确数量：*「将删除 N 条消费/充值记录，M 笔充值支出保留」*

**非储值卡（is_stored_value=0，含银行卡 bank 与自定义非储值卡）：**
- **直接删除，无需询问**——非储值卡消费是 type=expense+channel（ADR-020），不产生 type=card 流水，无关联虚空流水；渠道记录不挂 card_id，删卡无 FK 影响

**两类共同**：自动子分类随实体回收（卡片流水归【卡片】(2) 后删子分类）。

## 一致性说明

- 任何"保留"路径都不破坏数据完整性：外键置空而非悬空引用；类型转换满足 CHECK 约束（见 `设计-数据模型.md` §4.1）
- 保留路径类别归集：**卡片相关流水归【卡片】(2)**、普通流水归【其他】(1)（自动类别回收后 FK 不悬空，见 `设计-数据模型.md` §2.2）
- 删除类别保留 → `category_id` 改指【其他】(id=1)，type 不变
- **默认消费类别联动**：删除类别时若被 `card.default_category_id` 引用 → 置 NULL（回退自动子分类），不悬空（ADR-022）
- 自动类别随实体生命周期：实体删除时一并处理，不留孤儿类别（见 `设计-数据模型.md` §2.2）
- "删除"路径由 Repository 在**同一事务**内完成（删主 + 删关联 + 删自动类别），杜绝半删状态
- 与卡片余额、已还期数聚合天然兼容：流水没了，聚合自动重算
