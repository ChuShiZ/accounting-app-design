# 发布与在线更新

> 目标：用当前仓库 `ChuShiZ/accounting-app-design` 的 GitHub Release 发布正式签名 APK；App 在设置页检查更新。

## 1. 签名文件（不要提交）

正式 keystore 已生成在仓库外：

```
D:\project\accounting-app-design-secrets\
  jizhang-release.jks
  keystore.properties
  keystore.base64.txt
  GITHUB_SECRETS.txt
```

- alias：`jizhang`
- 包名：`com.self.jizhang`
- SHA-256：`AF:E5:EB:11:78:C7:A2:F4:6D:CC:28:86:AF:B7:F4:0E:77:EC:4A:38:A1:0A:08:FF:3F:5E:A3:89:8A:C4:24:3B`
- 密码保存在 `GITHUB_SECRETS.txt` / `keystore.properties`，请离线备份整个目录。
- 仓库已忽略 `android/keystore.properties`、`*.jks`、`*.keystore`。
- 以后所有正式版本必须使用同一个 keystore；丢失后无法覆盖升级。

## 2. 首次使用正式签名

以前安装的 debug 包和正式包签名不同，必须卸载一次：

```text
设置 → 应用 → 记账 → 卸载
```

然后安装 `jizhang-v1.0.0-universal-releasekey.apk`（debug 构建但已用正式 key 签名，仅用于试用/过渡）。  
之后的正式 release 版本可以直接覆盖安装，数据保留。

## 3. GitHub Actions Secrets

在 GitHub 仓库：

`Settings → Secrets and variables → Actions → New repository secret`

添加：

| Secret | 值 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `keystore.base64.txt` 全文 |
| `ANDROID_STORE_PASSWORD` | `GITHUB_SECRETS.txt` 中 keystore/store password |
| `ANDROID_KEY_ALIAS` | `jizhang` |
| `ANDROID_KEY_PASSWORD` | `GITHUB_SECRETS.txt` 中 key password |

工作流：`.github/workflows/android-release.yml`

## 4. 发版步骤

1. 修改 `jizhang-flutter/pubspec.yaml`：
   ```yaml
   version: 1.0.1+2
   ```
   `+2` 是 versionCode，必须每次递增。
2. 提交代码。
3. 打 tag 并推送：
   ```bash
   git tag v1.0.1
   git push origin main
   git push origin v1.0.1
   ```
4. GitHub Actions 在 Linux 上：
   - 构建 release APK
   - 使用正式 keystore 签名
   - 上传 `jizhang-v1.0.1.apk`
   - 上传 `latest.json`
   - 创建 GitHub Release
5. App 设置 → 检查更新，读取固定地址：
   ```
   https://github.com/ChuShiZ/accounting-app-design/releases/latest/download/latest.json
   ```

`latest.json` 格式：

```json
{
  "versionName": "1.0.1",
  "versionCode": 2,
  "tag": "v1.0.1",
  "apkUrl": "https://github.com/ChuShiZ/accounting-app-design/releases/download/v1.0.1/jizhang-v1.0.1.apk",
  "sha256": "...",
  "notes": "Release v1.0.1"
}
```

## 5. 说明

- Git 仓库本身不是更新服务器；APK 和版本清单走 GitHub Releases。
- 当前仓库是 public，不需要新建更新仓库。
- 如果以后 App 仓库改私有，需要另建一个 public repo 只托管 `latest.json` / Release。
- 本地 Windows 的 release 工具链有 `gen_snapshot` 兼容问题，正式 release 由 GitHub Actions Linux 构建。
- 工作流需要先配置 4 个 Secrets；未配置时不会产出正式包。
- App 内“检查更新”目前打开下载页（浏览器），不做静默安装；APK 由 Android 系统安装器确认。
